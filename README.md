# Проект: Реализация пользовательского списка на C для Python

## Описание проекта

Данный проект направлен на разработку пользовательской библиотеки для языка Python, написанной на языке C с использованием стандартного CPython API. Основная цель — создать собственную эффективную реализацию структуры данных «список» (аналог встроенного `list`), обеспечив комфортный интерфейс для работы из Python-кода.

## Цели проекта

1. **Реализация пользовательского списка на C**
   - Разработать полноценный тип данных, поддерживающий основные операции: создание, добавление, удаление, доступ по индексу, итерацию и изменение размера.
   - Обеспечить совместимость со стандартными протоколами Python (например, протокол последовательности).

2. **Интеграция с CPython**
   - Использовать CPython API для создания нового типа объекта.
   - Реализовать управление памятью (выделение, освобождение, изменение ёмкости) через стандартные механизмы Python (`PyMem_Malloc`, `PyObject_HEAD` и т.д.).

3. **Сравнение со встроенным списком Python**
   - Провести серию бенчмарков для операций: добавление в конец, вставка/удаление в середине, доступ по индексу, итерация.
   - Сравнить производительность и потребление памяти.
   - Проанализировать сильные и слабые стороны собственной реализации.

4. **Формулировка выводов**
   - Определить, в каких сценариях собственная реализация может быть конкурентоспособной или, наоборот, уступает встроенному списку.
   - Оценить сложность разработки подобных расширений на C по сравнению с чистым Python.

## План реализации

1. **Изучение CPython API** — основные типы, управление объектами, создание последовательностей.
2. **Проектирование структуры** — внутреннее хранение элементов (динамический массив `PyObject*`), управление ёмкостью.
3. **Написание кода на C**:
   - Определение структуры объекта.
   - Реализация методов (`__getitem__`, `__setitem__`, `append`, `insert`, `pop` и др.).
   - Сборка и установка модуля.
4. **Тестирование** (Python-обёртка для проверки корректности).
5. **Бенчмарки** (timeit, memory_profiler).
6. **Анализ результатов и оформление выводов**.

## Ожидаемые результаты

- Рабочий Python-модуль, предоставляющий пользовательский тип `CustomList`.
- Документация и примеры использования.
- Таблицы/графики сравнения производительности с встроенным `list`.
- Обоснованные выводы о целесообразности создания таких списков на C в реальных проектах.

## Критерии успеха

- Функциональная полнота (поддержка основных операций списка).
- Отсутствие утечек памяти.
- Стабильная работа при различных сценариях использования.
- Объективное сравнение с эталоном (встроенный список).

## Возможные направления для улучшения (после сравнения)

- Оптимизация стратегии роста ёмкости.
- Реализация специализированных методов (например, `extend`, `reverse`).
- Поддержка slicing’a.

## Выводы (предварительные)

> *Ожидается, что встроенный список Python, написанный на C и оптимизированный десятилетиями, будет превосходить самодельную реализацию по скорости и эффективности памяти. Однако процесс создания собственного списка даст глубокое понимание внутреннего устройства CPython, управления памятью и написания высокопроизводительных расширений. Проект также покажет, насколько сложно достичь «родной» производительности без низкоуровневых оптимизаций (например, использования механизма свободных списков, избегания лишних вызовов API и т.д.).*
