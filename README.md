### 🔍 Краткий анализ

**Где MyList оказался быстрее:**
-  **prepend** — вставка в начало (~0.88x от list) — MyList быстрее благодаря структуре односвязного списка
- **mul** — умножение списка (~0.71x от list) — эффективная реализация

**Где MyList значительно уступает:**
-  **append** — 1077x медленнее — основная причина: отсутствие динамического массива с амортизированным добавлением
-  **iteration** — 289x медленнее — накладные расходы на обход связного списка
-  **getitem** — 26x медленнее — доступ по индексу за O(n) против O(1) у list
-  **setitem** — 19x медленнее — аналогичная причина

**Где результат ожидаем:**
- **insert** / **popAt** — 6–9x медленнее, но для связного списка это нормально (поиск позиции за O(n))
- **reverse** — 3.6x медленнее — обход с перестановкой ссылок

---

### Выводы

1. **Сильные стороны MyList:**
   - Операции вставки/удаления в начало (`prepend`) — быстрее, чем у встроенного list
   - Умножение списка (`mul`) — эффективная реализация

2. **Слабые стороны (ожидаемые для связного списка):**
   - Доступ по индексу — O(n) против O(1)
   - Итерация — медленнее из-за обхода по ссылкам
   - Добавление в конец — нет амортизированного выделения памяти

3. **Общий вывод:**
   Реализация на связных списках показывает ожидаемые результаты. Для операций, где важен доступ по индексу или частая итерация, встроенный list остаётся предпочтительным. Однако для сценариев с частыми вставками/удалениями в начало MyList может быть эффективнее.
