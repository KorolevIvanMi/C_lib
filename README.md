# Проект: Реализация пользовательского списка на C для Python

## Описание проекта

Данный проект направлен на разработку пользовательской библиотеки для языка Python, написанной на языке C с использованием стандартного CPython API. Основная цель — создать собственную эффективную реализацию структуры данных «список» (аналог встроенного `list`), обеспечив комфортный интерфейс для работы из Python-кода.

## Текущий статус проекта

**Статус:** *Основная функциональность реализована, остались дополнительные возможности*

### Что уже сделано:
- Полноценная структура данных на C с динамическим массивом `PyObject*`
- Управление памятью (выделение, освобождение, изменение ёмкости) через `PyMem_Malloc`
- Модульная архитектура проекта:
  - `list_module.c` — основная реализация типа `List`
  - `core_module.c` — базовые операции управления памятью и структурой
  - `read_module.c` — операции чтения (доступ по индексу, итерация, поиск)
  - `update_module.c` — операции изменения (добавление, вставка, замена)
  - `delete_module.c` — операции удаления (pop, remove, clear)
- Базовые операции:
  - Создание списка (`List()`)
  - Добавление в конец (`append`)
  - Вставка элемента (`insert`)
  - Удаление элемента (`pop`, `remove`)
  - Доступ по индексу (`__getitem__`, `__setitem__`)
  - Проверка длины (`__len__`)
  - Итерация (`__iter__`)
  - Очистка (`clear`)
  - Поиск элемента (`index`)
  - Проверка вхождения (`__contains__`)
  - Сложение списков (`__add__`)
  - и т.д. есть возмодность посмотреть через help
- Стабильная работа и отсутствие утечек памяти (проверено через Valgrind)
- Базовое тестирование функциональности (`for_test.py`)
- Настроенная сборка через Makefile

### Что предстоит реализовать:
- Поддержка срезов (slicing) для `__getitem__` и `__setitem__`
- Метод `reverse()` — разворот списка
- Метод `sort()` — сортировка списка
- Метод `replace(old, new, start=None, end=None)` — замена элементов с индекса по индекс
- Полное сравнение производительности со встроенным `list`
- Умножение списка (`__mul__`)

## Установка и использование

### Сборка проекта

Для компиляции проекта выполните:
```bash
make 
```
Это создаст в папке `build/` итоговую библиотеку `mylist.so`.

Доступные команды Makefile:
- `make all` — полная сборка проекта
- `make clean` — очистка временных файлов


### Установка готовой библиотеки

Библиотека скомпилирована под Linux (x86_64) и представлена файлом `mylist.so`.

**Способы установки:**

1. **Локальное использование (рекомендуется)** — положите `mylist.so` в папку с вашим Python-скриптом и импортируйте:
   ```python
   from mylist import List
   ```

2. **Глобальная установка** — скопируйте файл в директорию site-packages вашего интерпретатора:
   ```bash
   cp mylist.so /usr/lib/python3.x/site-packages/
   ```
   или для виртуального окружения:
   ```bash
   cp mylist.so /path/to/venv/lib/python3.x/site-packages/
   ```

3. **Виртуальное окружение** — активируйте виртуальное окружение и скопируйте файл в его site-packages.

> **Важно:** Вручную скопируйте скомпилированный файл. Установщик (setup.py) не предусмотрен для простоты распространения. Проект скомпилирован под Linux, для других ОС потребуется перекомпиляция.

### Пример использования
```python
from mylist import List

# Создание списка
lst = List([1, 2, 3, 4, 5])

# Добавление элементов
lst.append(6)
lst.insert(2, 99)

# Доступ по индексу
print(lst[0])  # 1
lst[3] = 100

# Удаление
lst.pop()      # удаляет последний

# Итерация
for item in lst:
    print(item)

# Проверка длины
print(len(lst))
```

## Предварительные выводы

> Встроенный список Python, оптимизированный десятилетиями разработки, ожидаемо превосходит самодельную реализацию в большинстве сценариев. Однако процесс создания собственного списка дал глубокое понимание внутреннего устройства CPython, управления памятью и разработки высокопроизводительных расширений на C.
>
> Основные сложности, выявленные в ходе разработки:
> - Необходимость ручного управления ссылками (`Py_INCREF`/`Py_DECREF`)
> - Сложность реализации протокола последовательности
> - Тонкости работы с CPython API (ошибки, исключения, типизация)
> - Трудности достижения производительности встроенных структур без низкоуровневых оптимизаций (свободные списки, кэширование и т.д.)
>
> Проект показал, что создание эффективных расширений на C требует глубокого понимания как Python, так и C, а также значительного времени на отладку и оптимизацию. Тем не менее, такой подход может быть оправдан для специализированных структур данных с уникальными требованиями к производительности.
